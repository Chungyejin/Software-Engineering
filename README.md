##  유스케이스 명세서 템플릿
각 유스케이스는 아래 표준 포맷에 맞추어 작성 및 관리됩니다.
* **설명 (Descriptions)**
* **기본 흐름 (Basic Flow)**
* **예외 흐름 (Alternative Flow)**
* **사전 조건 (Preconditions)**
* **사후 조건 (Postconditions)**
* **확장 지점 (Extension Points)**

##  기능적 요구사항 (Functional Requirements)

시스템이 제공해야 하는 핵심 기능적 요구사항 정의 목록입니다.

| 항목 ID | 기능명 | 기능 설명 | 액터 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| **REQ-FR-1** | 주문 생성 | 고객은 주문서를 작성하여 상품 주문 요청을 할 수 있다. | 고객 | 주문 생성 그 자체 |
| **REQ-FR-2** | 주문 변경 | 고객은 주문을 요청하기 이전에 주문 내용을 변경할 수 있다. | 고객 |주문 생성하기 전, 장바구니 등에서 주문내역(품목, 수량 등)을 변경하는 경우.|
| **REQ-FR-.-** | 주문 취소 | 고객은 출하 전, 이미 생성한 주문을 취소할 수 있다. | 고객 | 주문은 생성했으나, 아직 출하하기 전에 하는 주문 취소. |
| **REQ-FR-3** | 반품 | 고객은 이미 출하된 상품에 대해 반품할 수 있다. | 고객 | 주문도 생성하고, 출하도 완료되었으나, 주문을 취소.|
| **REQ-FR-4** | 주문 승인 | 영업/판매 관리자는 고객의 주문에 대해 승인 요청을 받는다. | 영업/판매 관리자 |  |
| **REQ-FR-5** | 견적서 작성 | 고객 또는 내부 부서에서 견적서를 요청한다. 검토 후 공식 발행한다. | 영업/판매 관리자 |  |
| **REQ-FR-6** | 판매전표 발행 | 판매 관리는 판매가 완료된 주문을 확인하고 발행한다. | 영업/판매 관리자 |  |
| **REQ-FR-7** | 세금계산서 발행 | 출하 완료 후 자동으로 매출이 확정되며 전자 세금계산서를 발행한다. | 영업/판매 관리자 | 주문번호, 품목, 수량, 단가, 부가세 포함 |
| **REQ-FR-8** | 대금 청구 | 매출 확정 시점에 고객별 대금 청구서를 자동으로 생성 및 발행한다. | 영업/판매 관리자 | 결제기한/미수금 조회, ERP 회계 연동 |
| **REQ-FR-9** | 출하 지시 | 승인된 주문은 자동으로 출하 대기 목록에 등록되며 출하 지시를 내린다. | 재고 관리자 | 시스템은 재고량 검증 후 부족 시 경고 |
| **REQ-FR-10** | 입고 |구매 또는 생산을 통해 입고되는 물품을 등록하여 재고 수량을 증가시키고, 입고 내역을 관리한다. | 재고관리자 |  |
| **REQ-FR-11** | 재고 조회 | 품목별, 창고별 실시간 재고 현황 파악한다.| 재고관리자 | |
| **REQ-FR-12** | 재고 조정 |손실, 파손, 불량 등으로 인한 재고 수량 변화를 직접 시스템에 입력하여 수정한다.| 재고관리 | 손실, 파손, 불량 등으로 인한 재고 수량의 변화를 직접 데이터 수정 가능. |
| **REQ-FR-13** | 판매 출고 | 재고 담당자가 출하를 시스템에 최종 확정 처리하여, 해당 품목의 재고 수량을 자동으로 차감한다.  | 재고관리자 |  |
| **REQ-FR-14** | 재고 실사 | 현장 실사 데이터를 시스템에 반영하고, 시스템 상 재고 차이 분석하여 재고 담당자 승인 하에 재고 수량을 일치시킨다.  | 재고관리 | 현장에서 수집한 실제 재고 데이터를 시스템에 입력하고, 입력된 실제 수량과 기존 시스템상의 재고 수량을 자동으로 비교하여 재고 차이(재고 오차)를 계산 |
| **REQ-FR-15** | 반품 출고 | 재고 담당자가  반품 거래를 시스템에 최종 확정 처리하여, 해당 품목의 재고 수량을 복구한다. |재 관리자 |  |
